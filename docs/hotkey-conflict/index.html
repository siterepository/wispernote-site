The hotkey is taken.

The dictation key is a popular one. If something else on your machine answers it first, Wisper Note never hears the key at all — so change ours, or change theirs.

This page is written for the first desktop build. No build is published yet, so nothing here has been through a support queue — if what you see does not match what this page says, the page is wrong and we want to know.

What a conflict looks like

A taken key looks different from a broken app. With a conflict, nothing happens at all: no recording indicator, no message, no clipboard fallback. Often something else happens instead — a launcher opens, a window snaps, a menu appears.

If you see the recording indicator and the words still do not arrive, that is a different problem and it is on nothing typed. Two shortcuts can also both fire, in which case you get your text and something else you did not ask for.

Launchers, window managers, clipboard tools, screen recorders and input-method switchers all live in the same neighbourhood of the keyboard. Whichever registered the combination first wins, and macOS does not arbitrate.

Change the Wisper Note key

  1. Open Wisper Note’s settings from the menu bar icon, or press ⌘,.
  2. Go to General.
  3. Click the recorder next to Dictate (hold) and press the combination you want. It records what you actually press, so hold the modifiers.
  4. Wisper Note checks the new combination as you record it and tells you if it can see a conflict. It cannot see every one — an application that grabs keys at a lower level is invisible to that check — so test it in another app before you trust it.

The other direction works too, and is sometimes the better answer: if the program holding ⌥ Space is one you use more than dictation, change that one and leave ours alone.

Choosing a key that lasts

You will hold this key hundreds of times a day, so it has to be comfortable in one hand and hard to press by accident. Three things matter more than they sound:

  • Reachable with one hand. The other hand is on the mouse or holding a phone with the notes you are reading.
  • Not a single letter or a bare function key. You will hit it mid-sentence.
  • Not already doing something in the app you write in most. A conflict inside one application is the hardest kind to notice, because everywhere else it works.

The other shortcuts

Every shortcut Wisper Note registers is in the same pane, and every one of them can be changed or cleared. Clearing a shortcut you do not use is a legitimate fix for a conflict.

  • ⌥ Space — hold to dictate. The one this page is about.

The new key does nothing either

If a second, definitely-unused combination also does nothing, it is not a conflict. Two causes account for nearly all of these:

  • A password field is focused somewhere. While one is open, macOS stops applications reading keys from each other. Wisper Note copies instead of typing in that state, and if it never hears the key it does not start either. Click into an ordinary window and try again.
  • The microphone or Accessibility grant is missing. Both are on nothing typed, with the exact panes to open.

Still stuck

The fastest test is to set a deliberately absurd combination — something no other program would ever claim — and see whether that one works. If it does, you had a conflict. If it does not, the problem was never the key.

There is no support address on this page yet, because the mailbox is not monitored yet and an address nobody reads is worse than none. It goes here the day it is staffed.
